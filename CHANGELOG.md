# Changelog

All notable changes to the CyberRiskGuardian Ontology (CRGO). Versions follow [semantic versioning](https://semver.org/) as applied to ontologies: a minor version adds terms or data; term IRIs (`https://w3id.org/crgo/CRGO_nnnnnnn`) never change meaning or disappear, and retired terms are deprecated, not deleted. Each version records who approved what in `src/approvals.tsv`; design reasons are in `docs/decisions.md`.

### Fixed
- **Input validation of the query interface and MCP server** (NV-C01, NV-C02, NV-C03; `pipeline/query/identify.py`, `pipeline/mcp/crgo_server.py`). No SPARQL is built from raw input any more: ATT&CK ids (`T1566`, `T1566.001`, `TA0001`), requirement ids, scenario ids and IRIs, filter keys and labels, keywords and sectors are validated by shape, and string literals are escaped. Bad input raises `identify.CrgoError` and the server returns an error document `{"error": true, "code": ..., "message": ..., "details": [...]}` with `INVALID_ARGUMENT` (unknown `kind`, category, theme, framework or confidence, with the allowed values; oversized or malformed arguments) or `UNKNOWN_ID` (a scenario, technique or requirement CRGO does not hold), instead of a bare "Error executing tool". `limit`, `top`, `per_theme` and `max_total` are clamped to 1..200 (`limit=-1` returns one scenario, `10^9` returns at most 200); list arguments take at most 50 values of at most 100 characters (5,000 keywords are refused in milliseconds instead of running 45 s); unknown ATT&CK ids in a filter are reported in `unknown_techniques` rather than silently matching nothing. Tests: `tests/identify/test_identify.py` (16 new checks) and `tests/mcp/test_mcp_errors.py` (44 calls through the stdio server, repository unchanged outside `build/`).
- **Write-back path** (NV-C04; `pipeline/contracts/dss.py`, `crgo_server.py`). The schema is validated before the organisation is looked up (an empty document is `SCHEMA_INVALID`, not `UNKNOWN_ORGANISATION`); the output path is resolved with `realpath` and any path inside the repository except `build/` is refused with the new code `REPOSITORY_PATH` (also used when the file is not a `<name>-dss-proposed.ttl`), so a write-back aimed at `tests/samples/` no longer lands in the repository; `REFERENCE_NAMESPACE` is kept for IRIs only. Missing or unreadable organisation graph files return `INVALID_ARGUMENT`; a malformed `as_of` returns `SCHEMA_INVALID` in `crgo_risk_context` as it already did in the compliance and secops views. `error.schema.json` of the three contracts lists the new codes; the contract READMEs document them. `tests/contracts/test_dss_contract.py`: 36 checks (7 new, including a symlink into the repository).
- **`check.sh` no longer rewrites a tracked file** (NV-C07). `src/build_shapes.py` writes `build/crgo-shapes.ttl` by default and exits 1 when it is not isomorphic to the tracked `shapes/crgo-shapes.ttl`; `--write` rewrites the tracked file (done once for this release, so the file is reordered but isomorphic apart from the version). Step 10 uses the default.
- **Content review** (NV-C05; `pipeline/library/content_review_0111.py`, applied to `data/library/*` and, by targeted edits, to the committed `data/abox/crgo-library.ttl`, version 0.11.1 with a `skos:changeNote`). The theme rule for *physical and environmental* matched `fire` inside `firewall` and the rule for *advanced and multi-vector attacks* matched `evolution` (`pipeline/library/themes.py`, fixed): ten firewall families (LIB-F1346, F1347, F1352, F1353, F1371, F1399, F1404, F1405, F1407 → *networks and remote access*; F1422 Web Application Firewall Bypass → *applications and software development*) and the case scenario ACRB/ACRB-A1 (refines five of them) leave *physical and environmental*; LIB-F0006 (enterprise architecture complexity) moves to *IT management and investment*. The proposed second themes that became primary are dropped; *legacy, patch and configuration management* stays as second theme of F1399, F1404, F1405 and F1407. Seven family names lose a trailing colon (LIB-F1022, F1023, F1024, F1497, F1613, F1614, F1801; also their threat-event and treatment labels). `data/export/crgo-identification.json` regenerated (19 scenarios differ, version 0.11.1). `build_abox.py` picks a case scenario's theme deterministically on a tie. The 39 CIS v8.1 safeguards flagged `REVIEW:` are unchanged by decision and listed in `releases/0.11.1/release-notes.md`.
